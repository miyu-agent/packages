# Miyu package source

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

This is the official package source of Miyu. The index is published at <https://miyu-agent.github.io/packages/>, and the package files are in the releases of each package's own repository. `miyu pkg update`, `miyu pkg search` and `miyu pkg install <id>` all use this package source.

## What is in this repository

The table below lists the files in this repository and what each one does:

| File | What it does |
|---|---|
| `sources.toml` | Which kinds of sources are collected: official repositories, and community repositories that have the `miyu-package` topic |
| `miyu-rev` | Which version of the core repository the collection and the packing template use to read manifests: the content is one line holding a commit id. To upgrade, you only change this one file, and both the collection and the packing template follow it |
| `official.toml` | The official repositories; for each one, the `.miyu` files in its latest release are collected |
| `names.toml` | Which source repository each id belongs to: first come, first served, so the first repository collected under an id takes it, and the id stays with that repository for good. Newly taken ids are written back to this file by the collection |
| `blocked.toml` | Blocked ids or repositories, with the reason for each |
| `.github/workflows/collect.yml` | Collects once a day, signs the index and publishes it to GitHub Pages. It also runs when the rules change or when it is triggered by hand. It also counts the downloads of all releases of each package, keeps the data for the last 8 days in `stats.json` on GitHub Pages (unsigned), and writes into the index, for each package, when it went online, its download count and its downloads over the last 7 days |
| `.github/workflows/pack.yml` | The packing template for package authors |
| `.github/workflows/pack-selftest.yml` | The self-test of the packing template: when the template or `miyu-rev` changes, it packs `tests/hello` once on each of the three systems, without uploading to a release |

The index is signed with Ed25519, and the public key is compiled into the `miyu` program (key id `f9234109a4740be9`). If the signature of an index fails to verify, `miyu` rejects the whole index.

## Publish a package

Add `.github/workflows/release.yml` to the package's own repository:

```yaml
name: release
on:
  push:
    tags: ["v*"]
jobs:
  pack:
    uses: miyu-agent/packages/.github/workflows/pack.yml@main
    permissions:
      contents: write
    with:
      package: <package id>
```

After you make a tag (`v` followed by the `version` in `package.toml`), the packing template checks the manifest by the same rules Miyu uses when installing a package, packs it into a `.miyu` file and uploads it to the release for that tag.

- If the package folder is not in the repository root: set `folder`.
- If programs must be built before packing: set `build` to a piece of bash script.
- If the manifest lists `targets`: make one package file per system, using `strategy.matrix` to set `runs-on` and `target` for each one.
- The core version used for packing: when `miyu-rev` is not set, the template uses the `miyu-rev` in this repository's root, which is the same version the collection uses, so a package can never pack but fail to be collected (or the other way round). Set `miyu-rev` only when you need to try a new way of writing the manifest that this version does not support yet.

Community packages are collected automatically: give the repository the `miyu-package` topic and put a `.miyu` file in its latest release, and the daily collection run picks it up and marks it as a community package. Ids are first come, first served, and abusive ids or repositories are written into `blocked.toml`. Getting into the official list (`official.toml`) needs the project owner's approval.
